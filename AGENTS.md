# Бронь Сервис — стабильная CRM заявок

Это отдельный рабочий клиент, скопированный из `bronservis51-bot/bron-franchise`
на commit `6bfdf52`. Реальные данные и авторизация общие с основным приложением.

- Не синхронизировать код автоматически с основным кабинетом. Новая версия CRM —
  отдельная осознанная публикация с typecheck, тестами, сборкой и проверкой UI.
- Доступ только действующей роли `franchise_manager`; сервер проверяет права и
  отзыв сессии в каждом RPC. Пароль, пользователи и права не копируются и не меняются.
- Сохранять контракты `me`, `lead_list`, `lead_trash_list`, `lead_save`, `lead_move`,
  `lead_set_deleted`. Для изменения серверных контрактов проверять оба приложения.
- Лендинг `bronservice-franchise` отправляет `lead_submit` прямо в общую базу.
  Не менять приёмник, не дублировать отправку и не создавать копию очереди.
- Здесь нет средств миграции, seed, reset или администрирования общей базы.
  Новые функции разрабатывать вне рабочей БД; совместимые миграции — в основном репозитории.
- `bron.crm.*`, `bron-crm-local`, PWA scope `/bron-crm/` не пересекаются с основным
  приложением. Нельзя читать, очищать или переносить его сессию/очередь.
- Сохранять защиту от несохранённого ввода, идентификаторы повторов, контроль версии
  карточки и подтверждение удаления. Ошибка/таймаут не означают успешное сохранение.
- Дизайн: исходный логотип, Montserrat, #0f0f11, #c1c2c4, #fefefe; синий акцент
  сохраняется из существующего приложения по решению владельца.
- Проверять 320/360/390/430/768/1280/1366/1440/1920 px, текст 200%, заполненный и
  пустой канбан, диалоги, ошибки; горизонтальная прокрутка только внутри канбана.
- В git только код и публичный publishable key. Нет паролей, токенов сессии,
  service_role, выгрузок заявок и персональных данных.
- Разделение фронтендов не устраняет общий отказ Auth/БД или сетевого доступа.
  Не обещать работу без VPN без проверки на пострадавшем устройстве.
